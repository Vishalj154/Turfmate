# Database Relationships

This document outlines how different collections relate to each other in our NoSQL structure.

## Overview Diagram

```text
User
 |
 +---- makes --------> Booking --------> Venue
 |
 +---- saves --------> Favorite -------> Venue
 |
 +---- writes -------> Review ---------> Venue
 |
 +---- receives -----> Notification

Venue
 |
 +---- has ----------> Time Slots
 |
 +---- receives -----> Bookings
 |
 +---- receives -----> Reviews
```

## Referencing Entities

In Firebase Cloud Firestore, relationships are maintained using string document IDs.

- `users/{userId}`: A document inside the `users` collection. The `userId` is generated by Firebase Authentication.
- `venues/{venueId}`: A document inside the `venues` collection.
- `bookings/{bookingId}`: A document inside the `bookings` collection.

### Examples of Linking

- When a user makes a booking, the `Booking` document stores `userId` and `venueId`. This allows us to fetch all bookings for a specific user or venue.
- The `TimeSlot` document links to a `Booking` by setting its `bookingId` field to the created booking document's ID. This reserves the slot.
- A `Review` document stores both the `userId` and `venueId` so we know who wrote it and which venue it belongs to.
